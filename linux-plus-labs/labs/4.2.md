A shell script is a text file full of the same commands you type at the prompt, plus logic: variables, tests, loops, and functions. In this lab you learn each building block with small experiments, then put them together into a real admin tool that reads a CSV file of new employees, validates every row, creates the accounts, and reports on them. You finish by checking the script with ShellCheck and scheduling it with cron, which is exactly how scripts are used on the job.

### What you'll practice

- The shebang line `#!` and running scripts
- Variables: environmental, arguments, assignments (`alias`, `export`, `local`, `set`, `unalias`, `unset`), return codes `$?`
- Expansion: parameter expansion `${var}`, command substitution `$(foo)` and `` `foo` ``, subshell `(foo)`
- `IFS` (input field separator) and `OFS` (awk's output field separator)
- Test: `!`, `-d`, `-f`, `-n`, `-z`
- Comparisons: numerical `-eq -ge -gt -le -lt -ne`; string `>`, `<`, `==`, `=`, `=~`, `!=`
- Regular expressions: `[[ $foo =~ regex ]]`
- Conditionals: `if`, `case`
- Loops: `for`, `while`, `until`
- Functions

### How it works

When you run a script, the kernel reads the first line. If it starts with `#!` (called the **shebang**), the rest of the line names the interpreter to run the file with, such as `#!/bin/bash` or `#!/usr/bin/env bash` (which finds `bash` in your `PATH`). Without a shebang, your current shell guesses, which can go wrong. The file also needs execute permission (`chmod +x`) to be run as `./script.sh`; otherwise you can still run it with `bash script.sh`.

Bash reads each line, then performs **expansions** before running it. Think of expansion as filling in blanks on a form before handing it in:

```{.diagram}
 you type:    echo "Hi $USER, kernel $(uname -r), file ${f%.txt}.bak"
                       |              |                 |
 expansion:   variable / parameter   command          parameter expansion
                       |              substitution      (trim .txt)
                       v              v                 v
 bash runs:   echo "Hi student, kernel 6.8.0-45-generic, file notes.bak"
```

- **Parameter expansion** (`$var`, `${var}`, and forms like `${var:-default}`) inserts and transforms variable values.
- **Command substitution** (`$(command)` or the older `` `command` ``) runs a command and inserts its output.
- **Arithmetic expansion** (`$(( 2 + 3 ))`) does integer math.
- **Word splitting** cuts unquoted results into separate words using the characters in **IFS** (by default: space, tab, newline). This is why you should almost always put variables in double quotes: `"$var"`.

Every command finishes with an **exit status** (also called a **return code**), a number from 0 to 255. **0 means success**; anything else means some kind of failure. The special variable `$?` holds the status of the last command. `if`, `while`, `until`, `&&`, and `||` all make decisions based on exit status, not on output. Even `[[ ... ]]` is just a command that returns 0 (true) or 1 (false).

Variables come in two kinds. A **shell variable** exists only in the current shell. An **environment variable** has been exported, so child processes (programs and scripts you start) get a copy. A child can never change its parent's variables. That is also why a **subshell**, a child copy of the shell started with `( ... )`, cannot change variables or the current directory of the shell that started it. Inside functions, `local` keeps a variable private to that function.

Scripts get input from **arguments**: `$1`, `$2`, ... are the positional parameters, `$#` is how many there are, `$@` is all of them as separate words, and `$0` is the script's own name.

Finally, scripts make decisions with tests. `[ ... ]` (the same as the `test` command) is the old POSIX form. `[[ ... ]]` is Bash's improved version: it does not word-split variables, supports `&&` and `||` inside, pattern matching with `==`, and **regular expressions** with `=~`. Use `[[ ]]` in Bash scripts. Numbers are compared with `-eq`, `-lt`, and friends (or inside `(( ))`), while `==`, `<`, and `>` inside `[[ ]]` compare **strings** by sort order. Mixing these up is one of the most common scripting bugs.

2. Write a script that uses a shebang, arguments, and command substitution. You will create files with heredocs in this lab: `cat > file <<'EOF'` sends every following line into `file` until a line containing only `EOF`. The quotes around `'EOF'` stop the shell from expanding `$` while writing the file, so the script keeps its `$` signs. (You can also open the file in `nano hello.sh` and type the lines.)

    ```bash
    cat > hello.sh <<'EOF'
    #!/bin/bash
    # hello.sh - my first script
    echo "Hello, $USER. Today is $(date +%A)."
    echo "This script is called: $0"
    echo "You gave me $# arguments: $*"
    echo "The first argument is: ${1:-<none>}"
    exit 0
    EOF
    chmod +x hello.sh
    ./hello.sh one "two words" three
    ./hello.sh
    ```

    ```{.output}
    Hello, student. Today is Saturday.
    This script is called: ./hello.sh
    You gave me 3 arguments: one two words three
    The first argument is: one
    Hello, student. Today is Saturday.
    This script is called: ./hello.sh
    You gave me 0 arguments:
    The first argument is: <none>
    ```

    ::: explain
    **What just happened:** `#!/bin/bash` tells the kernel to run the file with Bash. Lines starting with `#` are comments. `$USER` is an environment variable set at login. `$(date +%A)` is command substitution. `$0` is the script name, `$#` the number of arguments, and `$*` all arguments joined into one string. Quotes made `"two words"` a single argument, so `$#` is 3. `${1:-<none>}` is parameter expansion: use `$1`, or `<none>` if it is empty or unset. `exit 0` ends the script with a success return code.
    :::

    greeting="Hello"

    greeting = "Hello"
    color=blue
    bash -c 'echo "child sees: [$color]"'
    export color
    bash -c 'echo "child sees: [$color]"'

    Hello
    greeting: command not found
    child sees: []
    child sees: [blue]
    color=blue
    color=blue
    after unset: []

    ::: explain
    **What just happened:** An assignment is `name=value` with **no spaces** around `=`. With spaces, Bash thinks `greeting` is a command. `bash -c '...'` starts a child shell: before `export`, the child does not see `color`; after `export`, it does. `env` (or `printenv`) lists only environment variables; `set` with no arguments lists all shell variables *and* functions. `unset` deletes a variable. #### Task 2: Expansions, subshells, IFS, and OFS

1. Try the most useful forms of **parameter expansion**. Type each line and compare with the output.

    ```bash
    file="/var/log/nginx/access.log.1"
    echo "${file}"
    echo "${#file}"
    echo "${file##*/}"
    echo "${file%/*}"
    echo "${file%.*}"
    echo "${file%%.*}"
    echo "${file/log/LOG}"
    echo "${file//log/LOG}"
    echo "${file:5:3}"
    ```

    ```{.output}
    /var/log/nginx/access.log.1
    27
    access.log.1
    /var/log/nginx
    /var/log/nginx/access.log
    /var/log/nginx/access
    /var/LOG/nginx/access.log.1
    /var/LOG/nginx/access.LOG.1
    log
    ```

    ::: explain
    **What just happened:** Braces `${...}` mark exactly where the variable name ends and allow transformations:

    | Form | Meaning |
    |---|---|
    | `${#var}` | length in characters |
    | `${var#pat}` / `${var##pat}` | remove shortest / longest match of `pat` from the **front** |
    | `${var%pat}` / `${var%%pat}` | remove shortest / longest match from the **end** |
    | `${var/a/b}` / `${var//a/b}` | replace first / every `a` with `b` |
    | `${var:offset:length}` | substring (offset starts at 0) |

    So `${file##*/}` works like `basename` and `${file%/*}` like `dirname`, without starting a new process. A memory trick: `#` is left of `$` on a US keyboard (front), `%` is right of it (end).
    :::

2. Handle empty or missing values with default-value expansions.

    ```bash
    unset name
    echo "${name:-guest}"
    echo "[$name]"
    echo "${name:=guest}"
    echo "[$name]"
    echo "${name^^}"
    ( echo "${missing:?is not set}" ); echo "status: $?"
    ```

    ```{.output}
    guest
    []
    guest
    [guest]
    GUEST
    bash: missing: is not set
    status: 1
    ```

    ::: explain
    **What just happened:** `${name:-guest}` *uses* a default but leaves `name` unset. `${name:=guest}` uses the default *and assigns it*. `${name^^}` converts to upper case (`${name,,}` for lower). `${missing:?message}` prints an error and, in a script, exits immediately; it is a quick way to require an argument, as in `path="${1:?Usage: script PATH}"`. It ran inside `( )` here so it would not affect your login shell.
    :::

3. Use both forms of **command substitution** and arithmetic.

    ```bash
    kernel=$(uname -r)
    logged_in=`who | wc -l`
    echo "Kernel $kernel, $logged_in users logged in"
    echo "Config dir: $(basename "$(dirname /etc/ssh/sshd_config)")"
    echo "Next year is $(( $(date +%Y) + 1 ))"
    ```

    ```{.output}
    Kernel 6.8.0-45-generic, 1 users logged in
    Config dir: ssh
    Next year is 2027
    ```

    ::: explain
    **What just happened:** `$(...)` and backticks both run a command and insert its output (trailing newlines removed). Prefer `$(...)`: it nests cleanly, as the `basename "$(dirname ...)"` line shows, and is easier to read. Backticks still appear in old scripts and on the exam, so recognize them. `$(( ... ))` does integer arithmetic.
    :::

4. See how a **subshell** isolates changes, compared with a `{ }` group that runs in the current shell.

    ```bash
    cd /tmp
    count=1
    ( cd /etc; count=99; echo "inside ( ): PWD=$PWD count=$count" )
    echo "after ( ):  PWD=$PWD count=$count"
    { cd /etc; count=99; echo "inside { }: PWD=$PWD count=$count"; }
    echo "after { }:  PWD=$PWD count=$count"
    echo "hello" | read -r word
    echo "word=[$word]"
    cd ~/labs/4.2
    ```

    ```{.output}
    inside ( ): PWD=/etc count=99
    after ( ):  PWD=/tmp count=1
    inside { }: PWD=/etc count=99
    after { }:  PWD=/etc count=99
    word=[]
    ```

    ::: explain
    **What just happened:** `( ... )` ran the commands in a child copy of the shell. Its `cd` and assignment vanished when it exited. `{ ...; }` only groups commands in the *current* shell (it needs spaces inside the braces and a `;` before `}`), so its changes stuck. The `read` example is a classic trap: each part of a pipeline runs in its own subshell, so `word` was set in a child that immediately exited. Use `read -r word <<< "hello"` or `while ... done < file` instead.
    :::

5. Control word splitting with **IFS** (input field separator).

    ```bash
    printf '%q\n' "$IFS"
    line="jdoe,John Doe,sales,/bin/bash"
    IFS=, read -r user full dept shell <<< "$line"
    echo "user=$user | full=$full | dept=$dept | shell=$shell"
    set -- one two three
    IFS=,
    echo "$*"
    unset IFS
    echo "$*"
    ```

    ```{.output}
    $' \t\n'
    user=jdoe | full=John Doe | dept=sales | shell=/bin/bash
    one,two,three
    one two three
    ```

    ::: explain
    **What just happened:** The default `IFS` is space, tab, and newline (`printf %q` shows invisible characters). Writing `IFS=, read ...` sets IFS **only for that one command**, so `read` split the line at commas and `John Doe` stayed together. `<<<` is a here-string: it feeds a string to a command's standard input. `"$*"` joins the positional parameters with the first character of IFS. `unset IFS` restores the default behavior. Changing IFS globally is risky, so prefer the one-command form.
    :::

6. Control output with **OFS**, awk's output field separator. awk is often used inside shell scripts to reformat data.

    ```bash
    awk -F: -v OFS=' | ' '$3 >= 1000 && $3 < 65534 { print $1, $6, $7 }' /etc/passwd
    echo "a b c" | awk -v OFS=, '{ $1 = $1; print }'
    ```

    ```{.output}
    student | /home/student | /bin/bash
    a,b,c
    ```

    ::: explain
    **What just happened:** `-F:` sets awk's *input* field separator to `:`. `-v OFS=' | '` sets the *output* field separator, which awk places between items separated by commas in `print`. The condition picks regular users (UID 1000 to 65533). In the second example, `$1 = $1` forces awk to rebuild the line using OFS, turning spaces into commas.
    :::

#### Task 3: Tests and comparisons

1. Use the **test** operators for files and strings. `test EXPR`, `[ EXPR ]`, and `[[ EXPR ]]` all return 0 when the expression is true.

    ```bash
    test -d /etc && echo "/etc is a directory"
    [ -f /etc/hostname ] && echo "/etc/hostname is a regular file"
    [[ -f /etc/nope ]] || echo "/etc/nope does not exist"
    [[ ! -d /etc/hostname ]] && echo "/etc/hostname is NOT a directory"
    empty=""
    word="hi"
    [[ -z $empty ]] && echo "empty has zero length"
    [[ -n $word ]] && echo "word is not empty"
    ```

    ```{.output}
    /etc is a directory
    /etc/hostname is a regular file
    /etc/nope does not exist
    /etc/hostname is NOT a directory
    empty has zero length
    word is not empty
    ```

    ::: explain
    **What just happened:** `-d` is true for a directory, `-f` for a regular file, `-z` for a zero-length string, and `-n` for a non-empty string. `!` reverses (negates) any test. `cmd1 && cmd2` runs `cmd2` only if `cmd1` succeeded; `cmd1 || cmd2` runs `cmd2` only if `cmd1` failed. Other common file tests: `-e` exists, `-r` readable, `-w` writable, `-x` executable, `-s` not empty, `-L` symbolic link.
    :::

    ::: warning
    With single brackets, always quote variables: `[ -n "$var" ]`. If `var` is empty and unquoted, the test becomes `[ -n ]`, which is true. `[[ ]]` does not have this problem, but quoting is still a good habit.
    :::

2. Compare **numbers** with the numeric operators.

    ```bash
    a=7
    b=10
    [[ $a -eq 7 ]] && echo "a -eq 7"
    [[ $a -ne $b ]] && echo "a -ne b"
    [[ $a -lt $b ]] && echo "a -lt b"
    [[ $a -le 7 ]] && echo "a -le 7"
    [[ $b -gt $a ]] && echo "b -gt a"
    [[ $b -ge 10 ]] && echo "b -ge 10"
    (( a <= b )) && echo "(( a <= b )) is true"
    ```

    ::: explain
    **What just happened:** All six lines print. `-eq` equal, `-ne` not equal, `-lt` less than, `-le` less or equal, `-gt` greater than, `-ge` greater or equal. Inside `(( ))`, Bash does arithmetic and you may use the familiar `<`, `<=`, `>`, `>=`, `==`, `!=` symbols on numbers, without `$` in front of variable names.
    :::

3. Compare **strings**. Here `==`, `!=`, `<`, and `>` mean text equality and alphabetical (sort) order.

    ```bash
    [[ "apple" == "apple" ]] && echo "== equal"
    [ "apple" = "apple" ] && echo "= equal (POSIX)"
    [[ "apple" != "pear" ]] && echo "!= different"
    [[ "apple" < "banana" ]] && echo "apple < banana"
    [[ "pear" > "banana" ]] && echo "pear > banana"
    [[ "report.txt" == *.txt ]] && echo "pattern match"
    [[ 10 < 9 ]] && echo "as strings, 10 sorts before 9"
    [[ 10 -lt 9 ]] || echo "as numbers, 10 is not less than 9"
    ```

    ::: explain
    **What just happened:** `=` is the POSIX string-equality operator (works in `[ ]` and `[[ ]]`); `==` is the Bash form. In `[[ ]]`, an unquoted right side of `==` is a glob pattern, so `*.txt` matched. `<` and `>` compare sort order, character by character, which is why the *string* `"10"` comes before `"9"` (because `1` sorts before `9`). For numbers, always use `-lt` and friends or `(( ))`.
    :::

4. Find out what happens with `<=` and `>=` on strings, and learn the alternatives.

    ```bash
    [[ "a" <= "b" ]] && echo yes
    [ "a" < "b" ]
    x="apple"
    y="banana"
    ! [[ $x > $y ]] && echo "$x sorts before or equal to $y"
    [[ $x < $y || $x == $y ]] && echo "same test, written out"
    printf '%s\n' "$x" "$y" | sort -C && echo "sort -C agrees: already in order"
    [ "$x" \< "$y" ] && echo "single brackets need an escaped \<"
    ```

    ```{.output}
    bash: syntax error in conditional expression
    bash: syntax error near `"b"'
    bash: b: No such file or directory
    apple sorts before or equal to banana
    same test, written out
    sort -C agrees: already in order
    single brackets need an escaped \<
    ```

    ::: explain
    **What just happened:** `<=` and `>=` are **not valid string operators** in `[[ ]]`; Bash reports a syntax error. They only work as arithmetic operators inside `(( ))`. To test "x sorts before or equal to y", negate the opposite test (`! [[ $x > $y ]]`) or combine `<` with `==`. `sort -C` returns 0 if its input is already sorted. In single brackets, a bare `<` is a **redirection**: `[ "a" < "b" ]` tried to read from a file named `b`. Escape it as `\<` there.
    :::

5. Match a **regular expression** with `=~`. A regular expression (regex) describes a text pattern. Bash uses POSIX extended regex, like `grep -E`.

    ```bash
    ip="192.168.100.10"
    re='^([0-9]{1,3})\.([0-9]{1,3})\.([0-9]{1,3})\.([0-9]{1,3})$'
    if [[ $ip =~ $re ]]; then
        echo "IPv4-like; first octet ${BASH_REMATCH[1]}, last ${BASH_REMATCH[4]}"
    fi
    [[ $ip =~ "^192" ]] || echo "quoted pattern is a literal string, not a regex"
    [[ $ip =~ ^192\. ]] && echo "unquoted regex matches"
    ```

    ```{.output}
    IPv4-like; first octet 192, last 10
    quoted pattern is a literal string, not a regex
    unquoted regex matches
    ```

    ::: explain
    **What just happened:** `^` anchors the start and `$` the end, `[0-9]{1,3}` means one to three digits, `\.` is a literal dot, and `( )` creates capture groups. After a successful match, Bash stores the whole match in `${BASH_REMATCH[0]}` and each group in `${BASH_REMATCH[1]}` and up. **Do not quote the regex**: quoting makes it a plain string. Storing the regex in a variable (`re='...'`) avoids quoting problems with special characters. Note this pattern still accepts `999.1.1.1`; checking each octet is 255 or less needs extra code.
    :::

::: checkpoint
**Checkpoint:** `[[ 9 -lt 10 ]] && echo num; [[ 9 < 10 ]] || echo str` prints both `num` and `str`. If you understand why, you have the most important comparison rule.
:::

#### Task 4: Make decisions with if and case

1. Write a script that uses `if`, `elif`, and `else` with file tests, and requires an argument.

    ```bash
    cat > checkfile.sh <<'EOF'
    #!/bin/bash
    # checkfile.sh - describe the path given as the first argument
    path="${1:?Usage: checkfile.sh PATH}"

    if [[ -L $path ]]; then
        echo "$path is a symbolic link to $(readlink "$path")"
    elif [[ -d $path ]]; then
        echo "$path is a directory with $(find "$path" -mindepth 1 -maxdepth 1 | wc -l) entries"
    elif [[ -f $path ]]; then
        echo "$path is a regular file of $(stat -c %s "$path") bytes"
    else
        echo "$path does not exist" >&2
        exit 1
    fi
    EOF
    chmod +x checkfile.sh
    for p in /etc /etc/hostname /bin /nope; do ./checkfile.sh "$p"; echo "  -> status $?"; done
    ./checkfile.sh
    ```

    ```{.output}
    /etc is a directory with 205 entries
      -> status 0
    /etc/hostname is a regular file of 11 bytes
      -> status 0
    /bin is a symbolic link to usr/bin
      -> status 0
    /nope does not exist
      -> status 1
    ./checkfile.sh: line 3: 1: Usage: checkfile.sh PATH
    ```

    ::: explain
    **What just happened:** `if` runs a command (here a `[[ ]]` test) and branches on its return code. Bash checks each `elif` in order and runs the first true branch; `else` catches the rest; `fi` ("if" backwards) closes the block. `-L` is tested first because `-d` and `-f` follow symbolic links (on Ubuntu `/bin` is a link to `/usr/bin`). `>&2` sends the error message to standard error, and `exit 1` returns a failure code to the caller.
    :::

2. Write a menu with `case`. `case` compares one value against several patterns, which is cleaner than a long `if/elif` chain.

    ```bash
    cat > menu.sh <<'EOF'
    #!/bin/bash
    # menu.sh - a tiny admin menu
    while true; do
        echo "1) Disk usage  2) Memory  3) Who is logged in  q) Quit"
        read -rp "Choose: " choice
        case "$choice" in
            1) df -h / ;;
            2) free -h ;;
            3) who ;;
            [4-9]) echo "Option $choice is not used yet" ;;
            q|Q|quit) echo "Bye"; break ;;
            *) echo "Unknown choice: '$choice'" ;;
        esac
    done
    EOF
    chmod +x menu.sh
    ./menu.sh
    ```

    Try `1`, `2`, `7`, `hello`, and finally `q`.

    ::: explain
    **What just happened:** `read -rp "Choose: " choice` shows a prompt and stores what you type (`-r` keeps backslashes literal). Each `case` branch is `pattern) commands ;;`. Patterns are globs: `[4-9]` matches one digit from 4 to 9, `q|Q|quit` matches any of three words, and `*` matches anything (the default branch, always last). `esac` closes the block. `break` leaves the `while true` loop.
    :::

2. Use `for` loops: over a list of files, over a range, and C-style.

    for f in /etc/*.conf; do

    **What just happened:** `for VAR in LIST; do ...; done` runs the body once per item. 3. Use `while read` to process the CSV file line by line, with IFS set to a comma.

    ::: explain

4. Use `until` to wait for something to happen. `until` is the opposite of `while`: it repeats as long as its command **fails**.

    ```bash
    rm -f ready.flag
    ( sleep 3; touch ready.flag ) &
    tries=0
    until [[ -f ready.flag ]]; do
        tries=$((tries + 1))
        echo "Waiting for ready.flag (check $tries)..."
        sleep 1
    done
    echo "Found ready.flag after $tries checks"
    ```

    ::: explain
    **What just happened:** The subshell `( sleep 3; touch ready.flag ) &` ran in the background (`&`) and created the file after 3 seconds, like a service finishing its startup. The `until` loop checked once per second until the test became true. Real scripts use this pattern to wait for a port to open, a host to answer `ping`, or a lock file to disappear, usually with a maximum number of tries so they cannot loop forever.

#### Task 6: Functions, local variables, and return codes

1. Write a script with several functions. Read it carefully before running it.

    ```bash
    cat > functions.sh <<'EOF'
    #!/bin/bash
    # functions.sh - arguments, local variables, and return codes
    counter=0

    is_even() {
        local n="$1"
        (( n % 2 == 0 ))
    }

    bump() {
        local step="${1:-1}"
        counter=$((counter + step))
    }

    scope_demo() {
        local counter=100
        echo "inside scope_demo: counter=$counter"
    }

    retry() {
        local max="$1"
        shift
        local attempt=1
        until "$@"; do
            if (( attempt >= max )); then
                echo "Giving up after $attempt attempts: $*" >&2
                return 1
            fi
            echo "Attempt $attempt failed; retrying..." >&2
            attempt=$((attempt + 1))
            sleep 1
        done
    }

    for n in 3 8; do
        if is_even "$n"; then
            echo "$n is even"
        else
            echo "$n is odd"
        fi
    done
    is_even 7
    echo "is_even 7 returned $?"

    bump
    bump 5
    echo "global counter=$counter"
    scope_demo
    echo "after scope_demo: counter=$counter"

    retry 3 test -e /etc/hostname && echo "found /etc/hostname"
    retry 3 test -e /no/such/file
    echo "retry returned $?"
    EOF
    chmod +x functions.sh
    ./functions.sh
    ```

    ```{.output}
    3 is odd
    8 is even
    is_even 7 returned 1
    global counter=6
    inside scope_demo: counter=100
    after scope_demo: counter=6
    found /etc/hostname
    Attempt 1 failed; retrying...
    Attempt 2 failed; retrying...
    Giving up after 3 attempts: test -e /no/such/file
    retry returned 1
    ```

    ::: explain
    **What just happened:** A **function** is a named group of commands, defined with `name() { ...; }` before it is used. Inside a function, `$1`, `$2`, `$@` are the *function's* arguments, not the script's. Key points:

    - `is_even` returns the status of its last command. `(( n % 2 == 0 ))` returns 0 (true) when the remainder is zero, so the function can be used directly in `if`.
    - `bump` changes the **global** `counter` because it does not declare it `local`.
    - `scope_demo` declares `local counter=100`, which hides the global variable only inside the function. The global stayed 6.
    - `retry` takes a maximum and a command. `shift` drops the first argument, so `"$@"` becomes the command to run. It uses `until` to retry and `return 1` to report failure.

    `return N` sets a function's return code (0 to 255). To send data back, `echo` it and capture it with `result=$(myfunc)`.
    :::

2. Turn on strict mode and see what each option does. Many professional scripts start with `set -euo pipefail`.

    ```bash
    bash -c 'set -e; false; echo "not printed"'; echo "status: $?"
    bash -c 'set -u; echo "value: $undefined_var"'; echo "status: $?"
    bash -c 'false | true'; echo "status: $?"
    bash -c 'set -o pipefail; false | true'; echo "status: $?"
    ```

    ```{.output}
    status: 1
    bash: line 1: undefined_var: unbound variable
    status: 127
    status: 0
    status: 1
    ```

    ::: explain
    **What just happened:** `set -e` exits the script as soon as a command fails (except in tests such as `if`, `while`, `&&`, `||`). `set -u` treats use of an unset variable as an error, which catches typos like `$USRE`. Normally a pipeline's status is that of its *last* command, hiding earlier failures; `set -o pipefail` makes the pipeline fail if *any* part fails. Together they make a script stop instead of continuing in a broken state.
    :::

    ::: warning
    With `set -e`, the arithmetic command `((count++))` fails when `count` is 0, because the expression's old value 0 counts as "false". Write `count=$((count + 1))` instead, as this lab does.
    :::

#### Task 7: Build the user-provisioning tool

Now combine everything into a tool an admin could really use. It reads `users.csv`, validates each row with a regular expression and a file test, and has four actions selected with `case`: `check`, `add`, `report`, and `remove`.

1. Create `~/labs/4.2/provision-users.sh`:

    ```bash
    cat > provision-users.sh <<'EOF'
    #!/usr/bin/env bash
    # provision-users.sh - check, add, report, or remove lab users listed in a CSV file
    # Usage: provision-users.sh {check|add|report|remove} [csv-file]

    set -euo pipefail

    readonly GROUP="labusers"
    SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
    readonly SCRIPT_DIR
    readonly LOG="${LOG_FILE:-$SCRIPT_DIR/provision.log}"
    readonly NAME_RE='^[a-z_][a-z0-9_-]{0,31}$'
    INVALID=0                                  # global counter of bad CSV rows

    log() {
        local msg="$1"
        printf '%s %s\n' "$(date '+%F %T')" "$msg" | tee -a "$LOG"
    }

    die() {
        echo "ERROR: $*" >&2
        exit 1
    }

    need_root() {
        if [[ $EUID -ne 0 ]]; then
            die "the '$1' action must be run with sudo"
        fi
    }

    valid_user() {
        local name="$1" shell="$2"
        if [[ ! $name =~ $NAME_RE ]]; then
            log "SKIP '$name': invalid username"
            return 1
        fi
        if [[ ! -x $shell ]]; then
            log "SKIP '$name': shell $shell is not installed"
            return 2
        fi
        return 0
    }

    user_exists() {
        id "$1" &>/dev/null
    }

    add_user() {
        local name="$1" full="$2" shell="$3"
        if user_exists "$name"; then
            log "OK   '$name' already exists"
            return 0
        fi
        useradd -m -c "$full" -s "$shell" -G "$GROUP" "$name"
        log "ADD  '$name' ($full, $shell)"
    }

    remove_user() {
        local name="$1"
        if user_exists "$name"; then
            userdel -r "$name" 2>/dev/null
            log "DEL  '$name'"
        fi
    }

    process_csv() {
        local action="$1" file="$2"
        local name full dept shell
        local line=0
        while IFS=, read -r name full dept shell || [[ -n $name ]]; do
            line=$((line + 1))
            if [[ $line -eq 1 || -z $name ]]; then
                continue                      # skip the header and blank lines
            fi
            shell="${shell%$'\r'}"            # strip a Windows line ending
            shell="${shell:-/bin/bash}"       # default shell when the field is empty
            if ! valid_user "$name" "$shell"; then
                INVALID=$((INVALID + 1))
                continue
            fi
            case "$action" in
                check)  log "VALID '$name' ($dept)" ;;
                add)    add_user "$name" "$full" "$shell" ;;
                remove) remove_user "$name" ;;
            esac
        done < "$file"
        log "Processed $((line - 1)) rows from ${file##*/}, $INVALID invalid"
    }

    report() {
        local members user
        members=$(getent group "$GROUP" | cut -d: -f4)
        if [[ -z $members ]]; then
            echo "No members in group $GROUP"
            return 0
        fi
        echo "Members of $GROUP on $(hostname) at $(date '+%F %R'):"
        for user in ${members//,/ }; do
            getent passwd "$user"
        done | awk -F: -v OFS=' | ' '{ print $1, $3, $5, $7 }'
    }

    main() {
        local action="${1:-}"
        local csv="${2:-users.csv}"

        case "$action" in
            check)
                [[ -f $csv ]] || die "CSV file '$csv' not found"
                process_csv check "$csv"
                ;;
            add)
                need_root add
                [[ -f $csv ]] || die "CSV file '$csv' not found"
                getent group "$GROUP" >/dev/null || groupadd "$GROUP"
                process_csv add "$csv"
                ;;
            remove)
                need_root remove
                [[ -f $csv ]] || die "CSV file '$csv' not found"
                process_csv remove "$csv"
                if getent group "$GROUP" >/dev/null; then
                    groupdel "$GROUP"
                fi
                ;;
            report)
                report
                ;;
            *)
                echo "Usage: ${0##*/} {check|add|report|remove} [csv-file]" >&2
                exit 2
                ;;
        esac

        if [[ $INVALID -gt 0 ]]; then
            exit 3                             # some rows were skipped
        fi
    }

    main "$@"
    EOF
    chmod +x provision-users.sh
    ```

    ::: explain
    **What just happened:** Walk through the script from top to bottom:

    - **Settings.** `set -euo pipefail` turns on strict mode. `readonly` makes constants that cannot be changed later. `SCRIPT_DIR` uses nested command substitution and `${BASH_SOURCE[0]}` (the script's path) to find the folder the script lives in, so the log always lands next to the script. `${LOG_FILE:-...}` lets a caller override the log location with an **environment variable**.
    - **Regex.** `NAME_RE` allows a lower-case letter or underscore first, then up to 31 lower-case letters, digits, underscores, or dashes, which matches the safe Linux user name rules.
    - **Small functions** with `local` variables each do one job. `valid_user` returns **different return codes** (1 for a bad name, 2 for a missing shell) so a caller could tell the failures apart. `user_exists` simply returns the status of `id`.
    - **`process_csv`** reads the file with `while IFS=, read -r`. The `|| [[ -n $name ]]` part also processes a last line that has no trailing newline. Parameter expansion strips a Windows carriage return (`${shell%$'\r'}`) and supplies a default shell (`${shell:-/bin/bash}`). `if ! valid_user ...` uses `!` to negate a function's return code.
    - **`report`** turns the comma-separated member list into spaces with `${members//,/ }`, loops over it with `for`, and formats the output with awk's `OFS`.
    - **`main`** uses `case` to choose the action from the first **argument** and exits with 2 for bad usage or 3 when rows were skipped, so a caller (or cron) can check `$?`. The last line, `main "$@"`, passes all script arguments to `main` with quoting intact.
    :::

### Exam corner

- The first line `#!/bin/bash` (shebang) selects the interpreter; make scripts executable with `chmod +x`.
- `$?` holds the last return code; 0 means success. `$#` is the argument count, `$1`... the arguments, `$@` all arguments, `$0` the script name.
- `export VAR` makes a variable an **environment variable** visible to child processes; `local` limits a variable to a function; `unset` deletes it; `set` lists variables or sets options (`-e`, `-u`, `-x`, `-o pipefail`); `alias` / `unalias` manage command shortcuts (not expanded in scripts by default).
- Parameter expansion: `${var:-default}`, `${var:=default}`, `${#var}`, `${var#pat}`, `${var%pat}`, `${var/old/new}`, `${var:offset:len}`.
- Command substitution: `$(cmd)` (preferred) and `` `cmd` `` (legacy). Subshell: `( cmds )` cannot change the parent's variables or directory.
- `IFS` controls how Bash splits words (`IFS=, read -r a b c`); awk's `OFS` sets the separator between printed fields.
- Numbers: `-eq -ne -lt -le -gt -ge` (or `(( ))`). Strings: `=`, `==`, `!=`, `<`, `>` (sort order). `<=` and `>=` are not valid string operators in `[[ ]]`.
- File and string tests: `-d` directory, `-f` regular file, `-e` exists, `-z` empty string, `-n` non-empty string, `!` negates.
- Regex: `[[ $var =~ ^regex$ ]]`, unquoted pattern, captures in `BASH_REMATCH`.
- `case` patterns end with `)`, branches end with `;;`, and the block ends with `esac`. `if` ends with `fi`. Loops end with `done`.
- `while` loops while a command succeeds; `until` loops while it fails; `for` loops over a list.

**Review questions**

1. A script contains `if [[ $count > 9 ]]` and `count=10`. The branch does not run. Why, and what is the fix?
2. Which command makes the variable `APP_ENV` available to programs started from the current shell?
    A. `local APP_ENV=prod`
    B. `set APP_ENV=prod`
    C. `export APP_ENV=prod`
    D. `alias APP_ENV=prod`
3. Given `f=backup.tar.gz`, what does `echo "${f%%.*}"` print?
    A. `backup.tar`
    B. `backup`
    C. `gz`
    D. `tar.gz`
4. Which loop keeps running as long as its test command returns a non-zero exit status?
5. What does `[[ -z $name ]]` test, and what is the opposite test?
6. A script runs `cp file /backup/; echo $?` and prints `1`. What does this tell you?

::: answers
1. `>` inside `[[ ]]` compares strings by sort order, and `"10"` sorts before `"9"`; use `[[ $count -gt 9 ]]` or `(( count > 9 ))`.
2. **C.** `export` marks the variable for the environment of child processes.
3. **B.** `%%.*` removes the longest suffix that starts with a dot, leaving `backup`.
4. The `until` loop.
5. It is true if `$name` is an empty (zero-length) string; `-n` tests for a non-empty string.
6. The `cp` command failed (a non-zero return code means failure); check its error message.
:::
